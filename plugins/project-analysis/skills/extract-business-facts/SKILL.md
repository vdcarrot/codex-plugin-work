# 从代码提取业务事实

把源码中的行为还原为可解释、可定位、有适用边界的业务事实。结论应回答：谁在什么条件下，以哪些输入执行什么动作，实际改变什么，何时完成，未完成时留下什么。按用户问题选择深度；不将代码目录或接口清单直接当作业务模型。

## 确定范围与事实准绳

- 以用户指定的项目、功能点或功能组为边界，记录代码版本及相关工作区改动。版本不可得时注明来源与读取日期，不编造基线。
- 默认解释当前代码表达的行为。需求、旧说明和注释可提供术语与查找线索；将其预期行为与已核实实现分开。商业目的没有依据时保留为推断。
- 范围尚不明确时，先做轻量侦察，再澄清会改变结论的歧义。能查明的代码事实先查再问。
- 局部任务只追踪影响该问题的上游前提、共享规则和下游效果；记录跨边界依赖，不扩展为整个依赖系统的分析。全项目任务先建立业务能力地图，再按能力核对，明确覆盖深度。
- 在现有项目规范与授权内取证。分析请求不自动授权修改业务代码、读取凭据、操作线上数据或发布成果；验证动作按实际需要和已有授权选择。

## 用问题驱动取证

### 1. 轻量侦察，形成可修正的问题清单

从真实入口、主要业务对象、参与者和业务效果识别系统轮廓。入口可以是页面操作、API、命令、消息、定时任务或数据管道。先定位相关源码与配置，避免为回答局部问题通读仓库。

把初步发现转成具体问题，例如“提交后已经成立什么”“哪些条件使确认失效”“为什么同样输入走不同路径”。按用户任务、结果影响和尚未消除的不确定性决定追踪顺序；新证据可以改变问题清单和模型，不要求起步就知道全部问题。

### 2. 沿实际路径追到业务效果

按项目结构追踪：**触发与调用方 → 实际输入 → 权限与放行判断 → 业务决策 → 写入或外部调用 → 后续处理与完成判据**。只检查与当前结论有关的环节，但不能跳过会改变结论的条件。

- 确认调用链可达、具体实现与路由绑定；区分当前入口、后台独立能力、内部辅助方法、历史兼容及未接入代码。方法存在不证明用户可以执行。
- 核对角色、对象归属、资格、授权有效期及状态前提。入口未见校验时继续检查中间件、策略层或被调用方，不能直接推断“没有权限限制”。
- 追踪输入来源、字段映射、默认值、条件必填，以及影响业务的单位、取整和配置分支。前端默认不等于服务端强制规则；仓库配置不等于部署实值。
- 找出实际创建或修改的对象、版本与业务事实。区分发起、受理、确认、执行成功，以及子对象完成与整体完成。
- 涉及异步或多步写入时核对事务边界、任务与回调、幂等、超时、重复调用和部分成功。明确失败发生在变化之前还是之后；恢复能力必须另有实现依据。
- 对外部服务或缺失实现，将已知调用约定与未知实际效果分开。不能凭接口名称补齐外部行为。

给关键结论保留文件、符号或接口、行号及基线，并说明证据具体支持哪部分判断。路径存在、枚举、注释或测试名称都不能代替执行条件与实际效果的核对。复杂事实的记录方式见 [事实记录与证据边界](./references/fact-records.md)，需要维护多条事实或交付底稿时按需读取。

### 3. 将事实组织为业务模型

用已核实事实归纳参与者、核心对象、事件、决策、约束及其关系。根据系统选择对象生命周期、角色任务、决策结构或协作流程，不强行生成单一状态链。

对“确认必须绑定当前版本”等候选业务约束，查清它在哪里校验、哪些事件会使它失效、谁负责维护，以及相关写入是否存在绕过路径。只在一个入口成立的保证，应限定为该路径；未核实所有相关路径时，不宣称系统级不变量。

宏观阶段必须能映射到具体对象与成立条件；多个对象共同成立、并行推进和独立失败应保留。把尚未验证的模型假设留在待确认项中，不为凑齐完整流程推定规则。

### 4. 用反例检查并修正结论

围绕关键问题改变一个条件，检查不同角色、状态、版本、配置或失败时点会怎样影响结果。按问题需要反查其他入口、共享写入、已有测试或迁移逻辑，寻找能推翻当前归纳的路径。

已有测试描述其覆盖的输入与预期；只有实际运行才报告本轮通过。静态源码分析支持有条件的实现判断，不能声称业务已在真实环境执行成功。必要的验证若无法完成，记录它影响哪些结论。

## 输出与完成标准

小范围问题直接给出业务结论、必要条件、关键证据和待确认项即可。多功能或全项目任务可提供能力地图、事实条目、关系说明及覆盖记录；按用户要求选择聊天回答或文件，不强制生成固定目录、图形或交互文档。

输出应能区分：

- **已核实实现**：可沿指定代码路径证明的条件与行为，注明入口及适用范围。
- **运行观察**：仅在实际观察过时记录版本、环境和结果。
- **推断或待确认**：缺少什么证据、有哪些竞争解释、会影响什么判断。

材料冲突时，先比较版本、入口、对象与条件；无法消除的冲突保留各自依据，不拼接成理想业务流程。覆盖记录说明核对了哪些语义、哪些未核对或排除；关联了接口不等于覆盖其所有业务语义。

当用户范围内的主要问题已有可追溯回答、关键分支与完成判据已明确、影响核心判断的不确定性已解决或显式界定时交付。全项目的抽样只能声明抽样覆盖；核心证据缺失时完成不受影响的部分并指出缺口，不以无限扩展分析代替结论边界。
